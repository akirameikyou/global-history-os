# 行事カレンダーと合氣道Focus の融合 — 構成の検討 v0.1

日付：2026-11-14　作成：α（Claude Code）
対象：
- 合氣道Focus：History OS（`global-history-os`）の `ueshiba/focusShell.html`。地球＋年代バー、年が単位。
- 行事カレンダー：別のサイト「植芝盛平フォーカス／合氣道」（`aikido-history-os`）。読んだだけで、変更はしていない。

## 1. いまの姿

| | 合氣道Focus | 行事カレンダー |
|---|---|---|
| 見せるもの | 植芝盛平の生涯、海外への広がり、世界の出来事 | 合気会の道場・団体の演武会・講習会・周年行事 |
| 時間の単位 | 年（1875年〜現在） | 日・時刻（開催地の時刻） |
| データ | `data/ueshiba_*.js` | `data/events.json`（29件、9か国。すべて調査見本 `sample: true`）、`orgs.json`（創立年→周年）、`dojos.json` |
| 画面 | 地球・年代バー・年譜・カード | 月の一覧・平面地図・今月の地球儀・活動の記録・周年・投稿の下書き |
| 出すもの | 画面だけ | 画面と `.ics`（`scripts/build_ics.py` が作る） |
| 言語 | 日本語 | 日本語・英語 |
| 決まり | 合気会と植芝盛平だけ／カメラは押した時だけ | 同じ。加えて、訂正・削除は48時間以内、見本は公開しない |

二つは、掲載の範囲・地球・地図の色まで、すでにかなり重なっている。違うのは、**時間の細かさ**（年と日）と、**運用の重さ**（行事は毎月の更新・訂正の窓口・.ics の購読）。

## 2. 融合の3つの形

### A. 片道リンク（いま）
Focus の右上「いまの行事 ↗」からカレンダーへ移るだけ。データは混ぜない。
- 良い点：何も壊さない。
- 弱い点：二つのサイトに見える。地球が二つある（Focus とカレンダーの「今月の地球儀」）。

### B. データでつなぐ（推奨）
カレンダーは**行事のデータの持ち主**のまま残る（行事の受け付け・確かめ・.ics・月の一覧・投稿）。Focus はそのデータを**読むだけ**で、地球の上に「いまの行事」を出す。
- Focus 側：年を「現在」まで送るか、「NOW」を押すと、行事の段が出る。地球に行事の点（金色）、左の枠に「今月とこれからの行事」。カードからは公式の告知と .ics へ移る。
- カレンダー側：「今月の地球儀」は Focus に任せて畳める（月の一覧・平面地図・周年・投稿は残す）。
- つなぎ目：`events.json` の決まった欄だけを読む（§3）。公開の場所がどちらも `akirameikyou.github.io` なら同じ場所なので、読み込みに特別な設定は要らない。
- 良い点：行事の運用を History OS の段階承認（main への反映）から切り離せる。行事は毎月更新し、歴史は落ち着いて直す、という速さの違いをそのまま保てる。
- 弱い点：二つのリポジトリの約束（データの欄）を守り続ける手間がある。手元の確かめでは、ポートが違うと読み込めない（§4）。

### C. 完全に一つにする
カレンダーを `global-history-os` の中へ移す（例：`aikido/calendar/`）。.ics の作成もそちらへ。
- 良い点：一つのサイト・一つの名前。
- 弱い点：History OS は多くの実験が入った大きな公開リポジトリで、main への反映は段階承認。毎月の行事の更新や、48時間以内の訂正と相性が悪い。英語の画面も History OS には無い。訂正の窓口の責任が History OS 全体にかかる。

## 3. B のつなぎ目（データの約束 v1 の案）

Focus が読むのは、`events.json` の `events[]` の次の欄だけ。

| 欄 | 使い道 |
|---|---|
| `id` | カードと .ics へのリンク（`calendar/evt/<id>.ics`） |
| `type` | 点の形（演武会・講習会・周年・合宿・交流・奉納・その他） |
| `title.orig`・`title.i18n.ja` | カードの題 |
| `start`・`end`・`tz` | 年代バーの位置と表示（開催地の時刻） |
| `place.lat`・`place.lng`・`place.name`・`place.city`・`place.country` | 地球の点と地名 |
| `organizer.name` | 主催 |
| `url` | 公式の告知 |
| `event_state`・`held_confirmed` | 予定・変更・中止・終了の表示 |
| `sample` | `true` は公開の画面に出さない（確かめの時だけ `?samples=1`） |

約束：カレンダー側は、この欄の名前と意味を変える時に版を上げる（`meta.schema: 1` を足す）。Focus は知らない版なら行事の段を出さない（壊れずに消える）。

## 4. 実装の要点（B を選んだ場合）

1. **時間の細かさ**：年代バーの右端に「現在」の区間を置き、そこだけ月の目盛りにする（万次郎版の年代バーは月の目盛りを持っているので、その描き方を使える）。年を送る操作は今のまま。
2. **NOW**：右上に「NOW」。押すと年を現在へ、年代バーの幅を「今日の前1か月〜後12か月」にする。カメラは動かさない（今の原則のまま）。
3. **色**：行事は金色（カレンダーの `--gold #e0c27a`）。History OS の色の約束（青＝本人、紫＝人物の関係、橙＝世界、ティール＝海外への広がり）に「金＝いまの行事」を足す。
4. **左の枠**：NOW の間だけ、World Events の枠を「今月とこれからの行事」に替える。下の枠（海外への広がり）はそのまま。
5. **読み込みの場所**：`data/ueshiba_config.js` に `EVENTS_URL` を足す（いまの `CALENDAR_URL` と同じ1か所）。手元の確かめは、カレンダーの配信が CORS を出さないので、同じポートで配るか、`events.json` の写しを置く。
6. **出典の扱い**：行事は主催者の告知へのリンクが出典そのもの。カードには「公式の告知 ↗」だけを出す（項目ごとの出典の札は付けない、の方針に合わせる）。

## 5. 先に詰めること（順番）

清水さんの「カレンダー・告知版を詰めてから融合を検討する」に沿うと：

1. **告知版を詰める**（カレンダー側。設計書の M2・M3）
   - 見本29件を、公開してよい行事として確かめ直す（`sample` を外せるもの）
   - 訂正・削除・掲載の申し出の窓口を決める（設計書 §9-3、未決）
   - 公開の場所と名前を決める（`aikido-history-os` をそのまま出すか）
2. **データの約束 v1 を決める**（§3。`meta.schema` を足すだけで、今の形はほぼそのまま使える）
3. **Focus に NOW の段を足す**（§4）。カレンダーの「今月の地球儀」を畳むかは、ここで並べて見てから
4. **3か月の中間確認**（設計書 判断4）で、C（一つにする）へ進むかを決める

## 6. 気をつけること

- **創立年の扱いが二つで違う**：Focus の「海外への広がり」には、周年の記述から逆算した設立年が入っている（以前の合氣道版のまま）。カレンダーは「推定の年は周年に使わない」と決めている。地球の上で並ぶと、同じ団体の年が食い違って見えるおそれがある。どちらの決まりに合わせるかを決める必要がある。
- **見本の取り違え**：いまの `events.json` は全件が `sample: true`。Focus は見本を出さない作りにする。
- **古い告知**：終わった行事を「告知のみ（開催は未確認）」と「開催を確認」に分けるカレンダーの決まりを、Focus のカードにもそのまま出す。
- **掲載の範囲**：どちらも「合気会と植芝盛平だけ」。融合しても変わらない。

## 7. 決めてほしいこと

1. B（データでつなぐ）で進めてよいか。将来 C にするかは、3か月の中間確認で決める案。
2. カレンダーの「今月の地球儀」を、融合のあと畳むか残すか。
3. 「海外への広がり」の設立年の決まりを、Focus とカレンダーのどちらに合わせるか（§6）。
4. 公開の場所（どちらも `akirameikyou.github.io` の下に置くか）。

## 追記（2026-11-15）：B で実装を始めた

清水さんの決定：北斎版と同じ「NOW」ボタンを採用。行事のサイトと Focus を同じデータ（告知資料）でつなぎ、開催情報を入れたら両方に出る仕組みにする。カードには「カレンダーで確認」のボタン。

### 仕組み（行事を1か所に入れると両方に出る）

```
  告知資料（主催者の公式の告知）
        │ 確かめて入れる（1か所だけ）
        ▼
  aikido-history-os/data/events.json  ← 行事のデータの持ち主（行事カレンダーのリポジトリ）
        │                     │
        │ scripts/build_ics.py │ 読むだけ（fetch）
        ▼                     ▼
  行事カレンダー             合氣道Focus（History OS）
  月の一覧・平面地図・.ics   NOW：地球に金の点・左下の枠に行事・年代バーに月の目盛り
        ▲                     │
        └──「カレンダーで確認 ↗」（その月を開く）
```

- Focus は `events.json` を書き換えない。入れる・直す・消すは、カレンダー側だけで行う。公開すれば次に Focus を開いた時に出る。
- `sample: true` の行事は Focus の公開の画面に出さない（いまは29件すべてが見本なので、NOW には「公開できる行事はまだ載っていません（確かめ中 29件）」と出る）。確かめは `?samples=1`。
- 場所の設定は `data/ueshiba_config.js` の `AIKIDO_SITE`（いまは `/aikido-history-os/`）1か所。公開でも手元でも同じ形で届くよう、サイトの根からの道で書いた。手元は `launch.json`「history-os-both」（ポート 8207、`C:\GitHub` を根に配る）で開く：
  `http://localhost:8207/_worktrees/ueshiba-focus/ueshiba/focusShell.html?samples=1`

### NOW の決まり（北斎版と同じ）
- NOW は時間の見方を「いま」へ切り替えるだけ。歴史の年と年代バーの幅はしまっておき、もう一度押すと戻る。カメラは動かさない。
- 年を動かす操作（年譜の行、章の「年へ」）をすると NOW は解ける。NOW の間は ‹ ▶ › ＋ − を止める。
- 左下の枠は、北斎版の HOLDINGS と同じく、枠を増やさずに意味を切り替える（海外への広がり → いまの行事）。
- 年代バーは「今日の1か月前〜13か月先」を月の目盛りで出す。行事は金の点（数日続く行事は線）。
- カード：日時（開催地の時刻）・場所・主催・種類・状態、ボタンは「カレンダーで確認 ↗」（その月）・「公式の告知 ↗」・「予定に追加（.ics）」・「地点を見る」。
